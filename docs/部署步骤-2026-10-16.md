## 2. 本次改动

需要同步到服务器的三部分：

**① 前端（`dist/`，已在本机构建好，部署前如有改动需重新 `npm run build`）**
- PPT 生成后直接下载，不再因"PowerPoint 动画未通过验收"拦截下载（`prep/PrepStudio.tsx`、`prep/CoursewareStoryboard.tsx`）
- "AI 润色"按钮改为按云端 AI 状态判断，接口地址从 `/api/prep/local-model/status` 改为 `/api/prep/lesson-ai/status`（`prep/UndergraduateDesignWorkflow.tsx`）

**② Node 接口（`server/index.js`）**
- `/api/prep/lesson-design/*` 走 20 分钟长超时通道，避免 AI 成稿超过 5 分钟时报 502
- 长超时通道为字符串请求体补 `Content-Length`

**③ 备课 Python 服务（`teacher-studio-service/backend/*.py`）**
- 教师版教案 AI 成稿：结果缓存 + 并发去重；校验失败先本地纠正，重试只修补上次输出（`lesson_design.py`、`lesson_ai_adapter.py`）
- PPT 导出不再调用 Windows PowerPoint/pywin32，只用 python-pptx 生成，可在 Linux 运行（`courseware.py`、`server.py`）
- 文字缩放在没有 Windows 宋体时改用 Linux 中文字体或字宽估算（`courseware.py`）
- PPT 下载名统一为 `shuzhiclass.pptx`，服务器存档为 `shuzhiclass_<随机码>.pptx`（`courseware.py`、`server.py`、`biomed_slides.py`）
- **删除本地 Ollama**：所有 AI 只走云端 `lesson_ai_adapter`；练习题改为调云端 AI；状态接口改名为 `/api/lesson-ai/status`（`lesson_design.py`、`server.py`）
- 修复单题重新生成练习题必定失败的问题（`server.py`）
- 本地已删除 `ollama_adapter.py`、`verify_courseware_views.py`。服务器上的这两个旧文件已无代码引用，可保留也可手动删除；部署脚本不会删除它们

## 3. 部署前检查（只读）

登录服务器后执行，确认环境满足要求：

```bash
cat /proc/loadavg; free -m
systemctl is-active shuzhi-prep; systemctl cat shuzhi-prep | grep -E "ExecStart|WorkingDirectory|EnvironmentFile"
pm2 list | grep shuzhi
/www/wwwroot/shuzhi/teacher-studio-service/.venv/bin/python -c "import pptx, PIL; print('deps ok')"
grep -c LESSON_AI_API_KEY /etc/shuzhi-prep.env /www/wwwroot/shuzhi/.env /www/wwwroot/shuzhi/.env.local 2>/dev/null
```

要点：
- **云端 AI 密钥**：Ollama 已删除，服务器必须配置 `LESSON_AI_API_KEY`，否则教案、成稿和练习题全部回退模板（教师版成稿会直接报错）。备课服务会从环境变量（`/etc/shuzhi-prep.env`）或 `/www/wwwroot/shuzhi/.env.local`、`.env` 读取。可选变量：`LESSON_AI_BASE_URL`、`LESSON_AI_MODEL`、`LESSON_AI_REASONING_EFFORT`。密钥值向用户索取。
- **python-pptx、Pillow** 必须已装在服务 venv 里；**不需要** pywin32 和 PowerPoint。
- 如果服务器上没有 `shuzhi-prep` 服务，先告诉用户，不要自行新建；部署脚本里的重启步骤会失败。

## 4. 部署（使用已改好的脚本）

脚本：`scripts/deploy_push_dist.py`（本机运行，需 `pip install paramiko`）。它在本机比对差异，只上传变化的文件，并限速传输。

```powershell
cd C:\Users\yuyiling\Desktop\shuzhi
$env:SSH_PASS = '<向用户索取>'
python scripts\deploy_push_dist.py            # 第一步：只读比对，列出待上传文件，不做任何修改
python scripts\deploy_push_dist.py --apply    # 第二步：确认清单后再执行
Remove-Item Env:SSH_PASS
```

也可以不用密码：脚本默认读取 `~/.ssh/id_ed25519`（本机已生成一把，公钥注释为 `shuzhi-deploy`，但**尚未**加入服务器 `authorized_keys`；是否加入由用户决定）。

`--apply` 会依次执行：
1. 把将被覆盖的备课服务 `.py` 备份到 `teacher-studio-service/backend/.bak_<时间>/`
2. 上传 `dist`（`index.html` 最后上传，切换是原子的）、`server/*.js`、备课服务 `.py`（不含 `test_*.py`）
3. `chown -R www:www`，`nginx -t`
4. 清理旧的 `assets/index-*` 文件
5. `nginx -s reload`，`pm2 restart shuzhi`，`systemctl restart shuzhi-prep`
6. 冒烟测试：首页、`/api/auth/me`、favicon、备课服务 `/api/lesson-ai/status`

**第一步的输出必须先给用户确认**，尤其是备课服务里被标为"更新"的文件：服务器上的 `server.py` 等如果有本地没有的改动，会被覆盖（虽有备份）。

## 6. 已知风险

- **带 3D 模型的 PPT 需要 Blender** 渲染四视图。Linux 上通过 `BIOMED_BLENDER_PATH` 指定 blender 可执行文件（写在 `/etc/shuzhi-prep.env`）；没有 Blender 时，有模型的课程导出 PPT 会报"未找到 Blender"，无模型的课程不受影响。另外 `shuzhi-prep` 限制了 `MemoryMax=512M`、`CPUQuota=50%`，Blender 渲染可能超限，需实测。
- 本次导出的 PPT **不再有点击动画**，是静态页面，这是有意为之。
- 后端测试 49 个通过 48 个；失败的 `HunyuanOnlyTests.test_polling_and_precision` 与本次改动无关，是之前就存在的问题。

## 7. 回滚

- 备课服务：把 `teacher-studio-service/backend/.bak_<时间>/` 里的文件拷回 `backend/`，然后 `systemctl restart shuzhi-prep`
- 前端与 Node 接口：脚本不备份 `dist` 和 `server/`；如需可回滚，执行 `--apply` 前先在服务器上手动备份：`cp -a dist dist.bak_<时间> && cp -a server server.bak_<时间>`
